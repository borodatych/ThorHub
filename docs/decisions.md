## 16.11.2026

- **Контроллер не работал ни в одной игре** → причина: половина evshim в процессе приложения не получала EVSHIM_BASE_PATH и брала зашитый `/data/data/app.gamenative`, приложение не будило Wine → каталог вычисляется по своему пакету из `/proc/self/cmdline`; libevshim.so лежит в jniLibs готовым файлом, пересобран из исходника NDK (заголовки SDL2 2.32.6 в Caches/ThorHub/sdl2)
- **Mordor на английском после «Возобновить»** → движок доверял частям уже лежащего файла по длине и пропускал депот по одному gid → файл с размером не по манифесту перепроверяется по чанкам, депот пропускается только при совпадении размеров всех файлов, маркер установки при расхождениях не ставится; Mordor исправляется через «Проверить файлы» (депот 241933 перекачивается почти целиком)
- **Окно отзыва на английском** → метки и кнопки в строковые ресурсы, ключи на сервер прежние, чтобы не ломать статистику GameNative
- **Mordor всё равно на английском после «Проверить файлы»** → настоящая причина: депоты 241931 и 241933 пишут одни пути, Steam оставляет файл депота, стоящего позже в appinfo (241931), а движок ставил по возрастанию номера → порядок appinfo сохраняется при разборе и передаётся движку, общий путь пишет и проверяет только депот-владелец; сверено со сборкой steamcmd: 0 расхождений по всем файлам, меню на русском
- **Загрузка висела часами** → блокирующий getaddrinfo без таймаута занял все рабочие потоки → резолв с таймаутом 5 с и кэшем, сторожевой таймер депота (60 с без прогресса, 3 срабатывания — ошибка), ограниченная остановка рантайма
- **Правки движка не попадали в APK** → libgndownload.so лежит в jniLibs готовым файлом, Gradle его не собирает → после правок Rust прогонять `tools/build-gn-download.sh` (хост-тег NDK теперь по `uname`) и коммитить .so
